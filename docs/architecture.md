# Base técnica v1

Estado: describe la arquitectura implementada y separa los componentes aún pendientes. El demo usa una tienda Next.js, una API comercial Node.js HTTP y PostgreSQL 17 compartido. La API todavía no usa NestJS y BullMQ no está integrado. Cambios incompatibles en estos contratos requieren revisión y versión nueva.

Arquitectura actual: Next.js consume la API Node.js por `/v1`; PostgreSQL guarda la verdad comercial. `packages/contracts` contiene DTO compartidos. API, tienda y bot trabajan con el mismo catálogo y transacciones PostgreSQL. La IA recibe herramientas acotadas; nunca SQL, permisos de administrador ni acceso directo a pasarelas.

Pendiente de producción: migrar la API a NestJS e incorporar BullMQ/Redis para notificaciones y expiraciones idempotentes. Culqi sigue en modo simulado; Meta requiere autorización y sus variables de entorno. La publicación externa está apagada por defecto. El diagrama histórico que conecta pagos a catálogo no debe implementarse: una publicación aprobada actualiza el catálogo local sin depender del resultado de Meta.

Demo inicial: PEN, recojo gratuito (pickup, 0 céntimos), sin descuentos ni delivery calculado por IA. Otras zonas/pedidos personalizados derivan a humano sin crear total inventado. Productos y publicaciones Meta simulados se identifican como tales. Culqi sandbox solo tras accesos y verificación documentada; por defecto simulador local, nunca cobros reales. URL de simulador no equivale a enlace Culqi.

Seguridad: sesiones opacas de servidor con cookie HttpOnly Secure SameSite y protección CSRF para panel. Clientes obtienen sesión anónima opaca: pedidos/conversaciones se vinculan al actor; conocer UUID no autoriza lectura. Sesión admin se provisiona fuera de la IA. WhatsApp verifica firma sobre bytes originales y normaliza teléfono E.164 contra lista autorizada en backend. Rechazar mensajes repetidos, actores inactivos y cambios de identidad. No confiar en role/channel enviados por cliente. Límites de frecuencia, tamaño e imágenes HTTPS de almacenamiento controlado; no descargar URLs arbitrarias (SSRF). No registrar tokens, cuerpos sensibles ni números completos; retención de conversaciones limitada por política de SORYNTEL antes de producción.

Ejecución posterior: backend → frontend (un trabajo Antigravity a la vez); integraciones después de API estable; QA sobre entregas. No activar agy hasta confirmación del operador. QA OpenCode/NVIDIA tiene incidencias de ciclo pendientes: confirmar resolución antes de asignar revisión. No cambiar motores, modelos, presupuesto ni crear agentes. Incorporar solo este commit inicial mediante cherry-pick local en worktree propio; implementaciones no se integran sin revisión humana. Validación integrada pendiente de esa autorización.
